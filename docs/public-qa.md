# 公开数据集小规模准确率对照

使用已有 `office-qwen3-vl-8b` 服务，固定抽样、提示词和生成参数，对同一道题依次执行模型直连、经过网关的 JSON、经过网关的 SSE。每题三条链路均独立推理，执行顺序按题轮换；并发为 1。

## 数据来源

| --- | --- | ---: | --- |
| GSM8K | [OpenAI 原始仓库](https://github.com/openai/grade-school-math)，test 1319 题，MIT | 20 | 提取最终 `####` 数值，去千分位后按十进制精确比较 |

## 固定协议

- 每个数据集使用独立的 `random.Random(seed + dataset_index)` 无放回抽样，种子 `20261113`；先保存题号和标准答案，再开始推理。
- 题目和标签来自上述公开数据，英文零样本提示词与本轮抽样协议由本项目编写。提示词不包含标准答案。数学题要求简短解题过程并以 `#### <number>` 结尾，阅读题要求仅输出 yes/no。
- 使用相同模型、消息、`temperature=0`、`top_p=1`，同题三条链路使用相同 seed。数学最多 512 个输出 Token，阅读最多 16 个。
- 共 40 道独立题目、120 次推理。任务错误、答案解析失败和接口异常均保留；错误响应计入计划题目分母，不通过重试筛掉失败。生成达到长度上限时单独计数。
- 每组 20 题完成后显示准确率，同时保留正确数、格式失败数、截断数。另比较网关和直连的标准化答案一致数、完整文本一致数及不同题号。
- 网关调用还核对上游 usage、持久回执、账户计数与账本，结束后吊销本轮 Key 并停用临时渠道，保留审计数据。

这是本机模型与网关的固定小样本对照；完整基准得分需要使用全量题目与对应的标准评测协议。逐条调用的时延受到前缀缓存和共享模型负载影响，作为运行记录保存。

## 评测准备时发现的参数透传问题

使用的 go-openai SDK 将 temperature 保存在带 `omitempty` 的 float32 字段中；显式零值无法表达为有效的 `temperature:0` 转发。真实 SDK 加本机 HTTP 接收端的回归，修复前在 JSON 和 SSE 两条路径均失败，证据为 `logs/temperature-zero-before.log`。

修复保留调用者是否显式提供 temperature，并在 SDK 生成的最终请求上补回该值；响应解析与 SSE 处理继续使用 SDK。请求身份也区分显式零值和省略参数，默认与非零 temperature 保留原有幂等身份编码。修复后的普通、流式回归及 Go race / 真实数据库测试通过；评分器另检查数值标准化、布尔标签解析及错误保留在分母的行为。

### BFCL 原生工具调用

评测代码为 `scripts/tool_benchmark.py`，数据和评分器来自 [伯克利官方仓库](https://github.com/ShishirPatil/gorilla/tree/6ea57973c7a6097fd7c5915698c54c17c5b1b6c8/berkeley-function-call-leaderboard)，固定提交 `6ea57973c7a6097fd7c5915698c54c17c5b1b6c8`。源码及各文件 SHA-256 存在 `/data/zjr/llm_gateway/toolchain/bfcl/<提交>/`。

固定抽取 Python 单工具 20、多工具选择 20、并行调用 10，共 50 题、150 次独立推理，逐题轮换直连 / 网关 JSON / 网关 SSE。模型参数为 `temperature=0`、`top_p=1`、每题相同 seed、最多输出 512 Token。网关用量逐次核对持久回执，并在结束时核对账户、请求用量和账本。

当前共享 Qwen 服务支持 `tool_choice=required`，未开启 `auto` 所需的服务端解析配置。本轮只选需要至少一次调用的任务，统一使用 required。这是本地固定子集协议，得分应标明类别、样本数和该设置。

函数文档中的类型按 BFCL 的官方 `GORILLA_TO_OPENAPI` 映射转为 OpenAPI Schema；函数名的点编码为下划线，Schema Map 键按 Go JSON 编码顺序排序。评分直接调用未修改的官方 `ast_checker`、类型映射及类型转换器。加载时仅提供本地模型名的静态名称编码配置，省去对全部在线厂商模型适配器的依赖。

流式工具参数按 `tool_calls[index]` 重组；检查结束标记、参数 JSON、函数选择、参数值与用量。正确／错误参数和缺失调用的官方评分对照，以及交错工具参数分片、截断流和坏 JSON 的本地回归均通过。

### 真实 Qwen 负载

评测编排为 `scripts/real_load.py`，实际发压直接使用已安装、未修改的 `vllm bench serve` CLI。固定抽取官方 BoolQ 原文，转换为其 custom JSONL 输入格式；`--custom-skip-chat-template` 使服务端应用一次聊天模板。数据、行号、种子和校验值保存在每轮目录。

- 普通负载：100 条固定输入，输出上限 64 Token，在并发 1、4、8 下分别测直连和网关 SSE，共 600 次调用。
- 长输出：8 条输入、512 Token 输出上限，直连和网关各一组，共 16 次调用。
- 长输入：由固定公开原文拼接为 5000 英文单词的输入，每组 8 条、输出上限 128 Token，直连和网关各一组，共 16 次调用。实际输入 Token 范围由本地 tokenizer 记录，同时检查请求体字节预算。
- 各组额外执行一次可追踪预热；CLI 的隐式就绪推理关闭，预热与正式发压分别记账。正式计划为 632 次调用，额外 10 次预热。
- 每组固定数据与种子，并发 4 时先网关后直连，其余先直连后网关。保存 TTFT、ITL、TPOT、端到端分位延迟、吞吐、实际输出 Token、逐请求文本和错误。
- CLI 的 TTFT 从发请求计到首个流式 choice 事件；模型输出 Token 与回执逐组核对，CLI 的输入长度是未包含服务端聊天模板的 tokenizer 估算值。
